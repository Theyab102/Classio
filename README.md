# Classio

Classio is a React study workspace for organizing documents, taking notes, reviewing flashcards and building presentations. Classio is free for all users and the study workspace opens in guest mode after the 13+ check.

Current implementation: [assistant and study workflow fixes](docs/CLASSIO-WORKFLOW-FIXES.md), [presentation/product report](docs/CLASSIO-PRESENTATION-REDESIGN.md), [security/privacy review](docs/CLASSIO-SECURITY-PRIVACY-REVIEW.md), and [combined development brief](docs/CLASSIO-CONSOLIDATED-REQUEST.md).

The [podcast and study-control repair](docs/CLASSIO-PODCAST-BACKGROUND-AND-UI.md) keeps podcast creation running across workspace navigation, preserves failed voice questions for retry, and makes count fields visibly editable. Reviewed, pinned development skills are included under `.agents/skills`.

## Run locally

Use Node.js 22 or 24. Run `npm ci`, then `npm start` for the browser app. The guest workspace and policy pages work with the browser app alone. Use Vercel’s local development server to test the server-side AI endpoints with a configured provider. Copy the setting names you need from [.env.example](.env.example).

- `npm run build:icons` packages the unchanged transparent logo into white-backed browser icons (requires Chromium).
- `npm run build` builds the browser app into `build/`.
- `CI=true npm test -- --watchAll=false` runs the focused regression tests.
- `node --test server/*.test.js` checks guest AI, transcription and provider failover with mocked providers.
- `npm run test:browser` tests the production build with Playwright on desktop, phone and tablet widths in both themes. Install Chromium with `npx playwright install chromium` or set `CLASSIO_CHROMIUM_PATH`. The test uses explicit AI/speech fixtures, real PDF/PPTX uploads and playable WAV bytes; it does not test live provider access. Screenshots are written to a temporary folder, or `CLASSIO_BROWSER_OUTPUT`.
- `npm run test:workflows` checks multiple chats, resizing, Arabic source grounding, custom counts, full-screen cards, voice selection, draggable appearance controls, guest note retention and source gestures at desktop/tablet/phone sizes. Providers are fixtures.
- `npm run test:notes` checks table editing, resizing and restoration, wide tables on phones, image review, and incremental course generation with truncation, failure and cancellation fixtures. See [the notes/course/sync follow-up](docs/CLASSIO-NOTES-COURSE-SYNC-FOLLOWUP.md) for the remaining production Firebase check.
- `npm run test:polish` checks folder/card spacing, proportional thumbnails, merged recent materials, equal audio tabs, presentation alignment, pointer/keyboard focus, actual theme transitions, reduced motion and same-origin font downloads on four device sizes. Its classification and voice-catalog responses are fixtures.
- `npm run test:sessions` checks guest refresh/tab isolation, encrypted uploads, automatic games, sound/muting, real browser recording with transcription fixtures, vision payloads and podcast voice interruption/resume across four device sizes. It also checks hijab selection and restoration.
- `npm run test:podcast` checks the always-visible transport, prepare-and-play, inline listening orb, manual/silence send, cancellation, spoken interruption, volume/mute, reduced motion and four responsive sizes. Recording, Web Audio analysis and playback are real Chromium operations; provider responses are fixtures.
- `npm run test:presentation` checks the staged editor, full preview, cutouts, crop/positioning, stale responses and actual PPTX exports on desktop, touch tablet and phone. Provider transports are explicit fixtures.
- `CLASSIO_BROWSER_SUITE=avatar npm run test:browser` runs the focused desktop/phone wearable workflow against the current build (the responsive matrix also runs).
- `npm run check:ai` checks the local server configuration and prints missing setting names, never their values.
- The policy URLs are `/privacy`, `/terms` and `/copyright`.

## AI providers and Vercel settings

The [AI upgrade report](docs/CLASSIO-AI-UPGRADE.md) documents routing, exact variable names, provider restrictions, recovery, security checks and remaining production configuration. This is React/CRA with Vercel API functions, not a Next.js migration.

Hosted requests use the authenticated same-origin `/api/study` route. Google accounts send a verified Firebase token; guests obtain a signed HttpOnly session plus a CSRF token from `/api/session`. Production quotas use shared Firestore transactions and fail closed without valid admin configuration. The public `/api/status` shows eligible provider names and general availability only. Run `npm run check:ai` server-side for setting/credential diagnostics; no secret values are printed.

The [A102 authentication repair](docs/CLASSIO-FIREBASE-ESM-FIX.md) fixes Firebase's CommonJS/ES-module dependency loading while retaining the current cryptography library. Its regression tests verify real signatures with synchronous `require(ESM)` disabled. The reviewed dependency archive and installed files are integrity-checked.

Keep **`Groq_Key`**, **`Gemini_Key`**, and **`Gemini_Key_packup`** exactly as deployed. Exact names take precedence over compatible legacy aliases. Groq, Cloudflare, OpenRouter, optional authenticated Ollama and auxiliary keyed image services accept a primary plus an optional `packup` credential. Only credential rejection (401/403) can use a backup. Shared rate limits, outages and timeouts move to another eligible provider. `Retry-After`, bounded retries, warm-instance circuits, capability/context checks and private request deduplication limit repeated work. Safety blocks stop fallback.

**Free-only is the default.** `AI_ALLOW_PAID=false` never silently selects paid inference. Providers require an authorized adult's current student-use eligibility confirmation; Groq/Cloudflare also require verified free account operation and hard billing limits. OpenRouter must list the selected model with zero catalog prices, with zero-price routing constraints. Gemini Developer API inference is blocked for Classio's school/minor audience even if legacy enablement flags are set. Missing optional backups do not block startup or other providers. No provider is activated by a key alone.

Use [.env.example](.env.example) for all names. Production requires a random `CLASSIO_SESSION_SECRET` of at least 32 characters, `AI_QUOTA_MODE=firestore`, `FIREBASE_SERVICE_ACCOUNT_JSON`, and at least one permitted free provider with its required confirmations. `AI_RATE_LIMIT_SECRET` can be separate; otherwise the session secret signs quota identifiers. Keep all credentials in server-only Vercel variables; never use `REACT_APP_`/`NEXT_PUBLIC_`. Build filtering and Gitleaks checks protect source, staged changes, history and exported bundles. No provider settings are provisioned by a Git push.

Large presentations/notes, courses, quiz batches and flashcards checkpoint before and between bounded requests. Resume keeps completed sections and the original settings. Account checkpoints use IndexedDB and the material's existing workspace sync; guest checkpoint bytes use the existing tab-session encryption. The tab orchestrates work while open; this is durable recovery, not a background server worker.

Optional `AI_ENABLE_BROWSER_LOCAL=true` exposes on-device WebLLM and Transformers semantic search with explicit download opt-in, size/progress information, compatibility checks and cache removal. Model weights are never downloaded automatically or bundled. PDF text extraction remains local.

Validation: `npm run test:ai-upgrade`, `npm run test:auth-browser`, `npm run test:server`, `CI=true npm test -- --watchAll=false --runInBand`, `npm run build`, `npm run check:audit`, and `PATH=/workspace/.onboarding/bin:$PATH npm run check:security`. Install the checksum-verified scanner with `sh scripts/install-security-tools.sh /workspace/.onboarding/bin`; activate hooks with `git config core.hooksPath .githooks`. CI runs the build, tests, dependency audit and full secret scan. The audit reports zero findings as of 18 November 2026. One fix uses a reviewed, integrity-checked local picomatch fork because upstream has no published fix; see [the session and audit follow-up](docs/CLASSIO-SESSION-AUDIT-FIX.md) for provenance and validation limits.

## Appearance and devices

The welcome page follows the device color scheme by default. Its Appearance selector offers Light, Dark and Use device setting; an explicit selection is remembered across visits. Theme changes animate unless reduced motion is requested. Eligibility and terms acknowledgment are also remembered in the same browser without retaining the date of birth. Guests keep their workspace through refresh in the same tab. Closing the tab ends the session.

The Library restores the original **Blank document, Upload document, Record audio and Website link** actions. **Create new** also contains AI notes, a course and folder creation. Search, type filters, sorting and recent materials use real user content. Phones use a hamburger menu containing every study tool. Tablet and PC sidebars scroll, including account and appearance controls. **AI Assistant** in navigation and visible page composers toggle the same assistant workspace with multiple independent chats. Its divider and Enlarge/Restore controls resize the panel on wider screens. The assistant reserves space on larger desktops and becomes a dismissible drawer on smaller screens. It sends only the current material, the current study activity, conversation and user attachments; Library context includes titles and folder names, not every document's contents. A failed workspace download offers a reload action with an explanation that guest work remains in the current tab session through refresh.

Character customization keeps Face, Hair, Outfit and Details, with original 3D previews, live staged changes, color choices, Randomize and Reset look. The expanded catalog includes 36 shaped tops, 33 hair options, 10 shoes, selectable bottoms, more hats/glasses/jewelry, independent wardrobe colors and accessories. Collars, sleeves, cuffs, seams and pockets use actual fabric geometry. Save changes commits the character; Cancel leaves the previous character intact. Profile and sidebar use the same renderer and saved character.

## Before public launch

1. **Domain and sign-in.** Connect the chosen domain to the existing Vercel project, verify DNS and HTTPS, and add the hostname to Firebase Authentication’s authorized domains. Test Google sign-in and direct navigation to all three policy pages on that domain. The favicon uses the existing Classio logo. [Vercel domain setup](https://vercel.com/docs/domains/set-up-custom-domain)
2. **Operator and privacy notice.** Configure the legal operator name and a monitored privacy address. Confirm the live data flows, retention and deletion process, provider settings and any required privacy disclosures for the markets you serve. The policy copy is a draft until those details are verified. Check the deployed site, Vercel integrations and Google tag settings for any analytics, advertising or replay code added outside this repository. [UAE data protection laws](https://u.ae/en/about-the-uae/digital-uae/data/data-protection-laws)
3. **Age and cloud permissions.** The neutral date-of-birth check runs before Firebase loads. The date stays in memory and only the decision and terms step are kept in this browser. Ineligible decisions expire after one day so eligibility can be checked again. This is a self-declared age screen. Review whether the service is directed at children and how reports of under-13 accounts will be handled. Verify Firebase access against your actual project. [firestore.rules](firestore.rules) is an owner-only baseline for personal folders and notes. It denies client access to other collections, including legacy group data and AI rate counters. Review and test it in staging before applying it to an existing project. Also check any live Storage and Realtime Database rules. [FTC COPPA guidance](https://www.ftc.gov/business-guidance/resources/complying-coppa-frequently-asked-questions)
4. **AI credentials and limits.** Configure a server-only provider key and the quota mode described above. Rotate keys previously exposed in screenshots or browser builds. Test guest text, images and audio from the production origin. Guest and signed-in requests use the same limits. Counters use short-lived HMACs of IP addresses; instance mode is not a shared hard spending cap. Verify provider retention and settings. Review Groq’s conditions for serving minors. The Gemini Developer API terms exclude applications likely to be used by under-18s. [Groq Services Agreement](https://console.groq.com/docs/legal/services-agreement) · [Gemini API terms](https://ai.google.dev/gemini-api/terms)
5. **Copyright.** Set a monitored reporting address and decide how reports, counter-notices and repeat infringement will be handled. If you seek U.S. DMCA safe-harbor protection for hosted user content, complete the Copyright Office registration, publish the designated agent’s name, mailing address, phone and email on the copyright page, and maintain the designation and process. [U.S. Copyright Office Section 512 guidance](https://www.copyright.gov/512/)
6. **Marketing email.** If you send marketing email, include a working unsubscribe link, required sender information and postal address, and maintain a suppression list. [FTC CAN-SPAM guide](https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business)

## Workspace behavior

Signed-in users keep an account-specific cached folder list. Cloud records are restored through the same Firebase account. The previous unscoped `classio_v2` entry stays in browser storage because it has no account identifier. If that entry contains the only copy of old offline work, recover it in the original browser before clearing site data. Original personal files are still stored separately in that browser. Guests can use all the study tools and download results. Their workspace survives refresh in the same tab and ends when the tab closes. The Library’s optional sign-in button imports the guest workspace into the signed-in account. Notes, progress and supported file metadata sync to Firebase. Original uploads remain on the device where they were added.

The built app serves DM Sans, Fraunces, Caveat and KaTeX fonts from its own assets. Website notes use `/api/source` to read a public page with its actual tables and figures. The reader checks public DNS addresses, pins the connection and validates redirects. Source figures retain credits; blocked or sign-in-only pages offer manual text entry.

Signed-in assistant history has an account-specific browser cache and an owner-only cloud preference document at `users/{uid}/preferences/assistant`. Deploy the updated [Firestore rules](firestore.rules) to enable that cloud path, after reviewing them against existing project collections. If cloud saving fails, the panel reports that history is saved in this browser only. Guest chat text survives refresh in the same tab and ends with that tab session. Attachment image bytes are not saved in conversation history. Nested presentation tables are encoded losslessly for Firestore and decoded on restore; legacy documents remain supported.

## Study tools

- **Notes** combines writing, AI note generation and lessons in one workspace. Its compact toolbar supports fonts, sizes, headings, lists, editable tables, images and KaTeX equations. HTML downloads include native MathML for equations. Generate notes inserts the formatted result directly into the editor. Existing writing is preserved by appending; explicit Organize can replace unchanged writing, and generation can be undone. The image picker searches Wikimedia Commons and shows image credits. When Include relevant images is selected, generation resolves image markers into actual figures beside the closest matching explanation, including grouped markers. Source PowerPoint images are preferred where relevant, and Wikimedia vector diagrams can use their rendered thumbnails. Missing images leave readable notes without technical placeholders. Existing notes can use Images → Place suggested images to repair old suggestions without regenerating writing; formatting and existing figures are preserved, with Undo available. Generation, equations, images and saved versions open in dismissible dialogs. Notes save automatically to workspace state; named versions and HTML downloads remain available from Note options.
- **Document viewers** render original PDF pages locally and keep their proportions and scale during page navigation. PDF text search highlights supported text. PPTX search finds parsed native slide text; the viewer supports native text, images and tables. Both viewers retain zoom, page position and page-specific pen/highlighter strokes. Annotation tools offer round color swatches and three stroke sizes: Fine, Medium and Broad. Complex PowerPoint effects are limited by the existing native renderer; the original file is downloadable.
- **Presentations** creates decks from topics or actual source material, with visual Lecture, Editorial and Visual layout choices, theme cards and optional generated alternatives. A large preview includes a filmstrip, navigation and full-screen mode. The staged slide editor provides text/media/layout/AI tools, drag/resize, crop, background-removal comparison, undo/redo and unsaved-change protection. Title, Content, Image, Comparison, Timeline, Summary, Table and Quote slides share preview/export geometry. Export as native PPTX where supported, with vector equation artwork and alpha-preserving figures, or print to PDF.
- **Guided lessons with questions**, selected from the Notes mode menu, turns a topic, document or note into structured explanations, worked examples and knowledge checks. The outline, progress, answers and active lesson are saved. Browser read-aloud appears where supported. Lesson explanations can be added to notes without losing existing writing.
- **Quizzes** generates validated questions from the selected material, with difficulty/count settings, hints, checked answers, explanations and results. Attempts and progress stay with the file.
- **Flashcards** provides animated question/answer cards, editing, search, category filters, spaced review, study shortcuts and TSV downloads. Generated cards append by default. Replacing cards or deleting one requires confirmation. Missed cards are due again in ten minutes; successful reviews use gradually longer intervals. Existing study games remain accessible separately.
- **Record audio** can turn uploaded recordings up to 2.8 MB into a transcript and notes. It can also use compatible browsers for live dictation. Keep the original file if an upload exceeds the limit or transcription is unavailable.
- **Podcasts** creates a grounded two-host script and requests real speech audio for each turn from the existing `Theyab102/classio-tts` Hugging Face Space. The browser combines the actual decoded audio into a playable WAV. Controls use real media duration and support play/pause, seek, speed, volume, timed sections, transcript speakers and saved playback position. Transcripts and episode history remain available if speech generation fails; a player is shown only when audio exists. Speaker labels remain in the transcript and are removed before speech synthesis, including when rebuilding older audio. “Ask the hosts aloud” pauses the episode, records a question, transcribes it through `/api/study`, generates a section-grounded reply and plays a real spoken answer before resuming. Typing is available as a fallback. This is a recorded question-and-answer flow; it requires microphone permission, transcription and the speech service. Voice discovery reports when only one service voice is available. Binary audio stays on the creating device (temporary memory for guests, IndexedDB when signed in); metadata/transcripts sync with the file. Set `REACT_APP_CLASSIO_TTS_URL` to an empty value at build time to disable the speech integration. Live speech service availability must be tested after the Space wakes. [Classio TTS Space](https://huggingface.co/spaces/Theyab102/classio-tts)
- **Website and video links** accept readable public webpages as well as videos, with a link-themed empty state and manual source-text entry. YouTube videos first try `/api/transcript`, which retrieves actual available YouTube captions with bounded requests and allowlisted hosts. Existing transcript fallbacks and manual transcript entry remain. Missing captions never turn into invented title-based notes.

Equations use a shared Markdown/LaTeX renderer across notes, guided lessons, quizzes, flashcards, link notes and the assistant. It preserves backslash and dollar delimiters before Markdown parsing, renders fractions, roots, units and subscripts with KaTeX, and recovers supported notation in older saved content. Code examples stay code. Headings, emphasis and GFM tables render as rich content.

The assistant lives in a collapsible right-side panel with an Ask Classio button when minimized. Greetings use a real, small AI request without reading or resending the open file. Study questions send bounded, relevant material excerpts and recent history. Groq can try a second listed compatible model when the first is busy; model cooldowns are separate from credential failures and oversized requests do not disable later small questions. The original logo now uses `ClassioLogo-transparent.png`, with the white backdrop removed for both themes; the original source asset is retained. Character previews now render original Three.js meshes with lighting and shadows, full-body rotation and the existing customization fields. Hairstyles wrap the head with a higher forehead hairline, lower face-mounted eyebrows and eye-length fringes on selected styles. Static renders provide a fallback on devices without WebGL2; no third-party character assets are used.

Dropdowns use a shared custom combobox with keyboard navigation, type-ahead, outside-click dismissal and screen-reader semantics. The notebook mode menu includes descriptions so guided lessons are easy to discover. The sidebar has a dedicated collapse/expand button; a file keeps Library, Search, AI and its study tools in focus. Study Guides stays in the Library, with Settings under the avatar in the persistent account area. Selected navigation items have a complete outline. Game cards, answer surfaces and presentation controls use readable colors in both themes. Motion is brief and disabled when reduced motion is requested.

## Character customization, visual styles and presentation images

Face, Hair, Outfit and Details keep their built-in 3D choices, custom colors, preset randomizers, rotation, staged save/cancel and undo/redo. The experimental sketch creator and community gallery have been withdrawn from the character UI: generating a texture on an existing mesh did not meet the requested sketch-to-new-wearable-geometry behavior. Existing worn assets and saved designs are preserved, with wear, remove and download controls. The prototype code and server adapters remain for future development; the current UI does not offer new AI-generated hair, clothes or publication.

Presentation generation has a wrapping **Design & style** field beside the main Generate action. It requests actual designs from the model, including safe patterns and typography, rather than always presenting three canned templates. One design applies directly; optionally request two or three generated alternatives. Style instructions apply during generation and can be cleared; existing content stays available until the new deck succeeds. Standard themes clear the previous custom styling. Checkerboards, dots, grids, stripes and ruled backgrounds render in the preview and export as native PowerPoint shapes. Outputs cannot inject arbitrary CSS or scripts. Model accuracy still depends on the configured provider.

Uploaded PDFs and PowerPoints provide real file thumbnails. Notes and presentation generation receive a numbered catalog of source figures and insert selected actual file images near their explanations. PDF figures use the original page render; PowerPoints use embedded pictures. Originals must be available on the current device. File sources are preferred and web fallback is opt-in for presentations. Existing images are preserved when finding additional matches. **Remove Background** uses `REMOVE_BG_API_KEY`, previews a real alpha cutout, preserves the original and supports undo; diagrams retain their backgrounds by default.

Optional web search supports Wikimedia Commons, plus `PEXELS_API_KEY`, `UNSPLASH_ACCESS_KEY`, or `GOOGLE_IMAGE_SEARCH_KEY` + `GOOGLE_IMAGE_SEARCH_CX` server adapters. Credits and source links stay with selections and PowerPoint notes. Unsplash selections use its download-tracking endpoint. Provider availability, account limits and licenses still apply.

Phone slide actions wrap below the title and preview. File cards fill the available column, color swatches stay circular, and text instructions wrap instead of scrolling sideways. Shared visual-viewport handling keeps the assistant, character editor, dialogs and pickers within the visible keyboard area. Annotation Undo/Redo stay visible beside the tools and retain Ctrl/Cmd+Z and redo. A stylus or mouse draws; one or two fingers scroll and swipe between source PDF pages or PowerPoint slides with the pen selected. Drawing options offers explicit finger drawing; two fingers still navigate and cancel any provisional finger stroke. Source pages follow the swipe while the adjacent page enters from the opposite edge. Completed turns slide both pages together; short and boundary swipes return to the current page. Buttons and keyboard navigation use the same direction, and reduced-motion mode switches immediately. Zoomed documents pan horizontally before changing pages. Study sound effects have a stronger envelope and retain their on/off control.

Natural-language style controls preview validated colors, typography, spacing, paper patterns and corners before applying them. Notes support explanation level, layout, length and custom instructions. File styles carry into the related study tools; Settings provides an app-wide style scope. Reset, cancel and previous-style restoration are available. Model outputs cannot inject CSS, URLs or scripts.

The podcast Ask button stays inline below the hosts and morphs into a listening orb. Click it again to send, or pause for three seconds after speaking to send automatically. Cancel stops capture and pending work. The answer plays aloud; the episode resumes from its saved position if it was playing before the question. Volume and mute apply to both the episode and the answer. Playback controls stay visible before audio is prepared, and Play can prepare the existing transcript and start it. Open text tutor provides the text alternative. Silence detection uses a local energy heuristic and cannot guarantee perfect detection in every acoustic environment.

Provider credentials use the centralized primary/optional-backup registry described above. Shared quota exhaustion never rotates through keys from one provider. Gemini's adapter remains implemented and blocked for this student audience. Generated sections save durably and can resume after a provider failure or refresh; existing completed student work remains available.
